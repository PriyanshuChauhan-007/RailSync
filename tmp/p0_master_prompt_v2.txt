CORRECTION 1 - VALIDATOR REJECTION MUST HAVE EXPLICIT RECOVERY
SEMANTICS
Replace the original escalation wording with the following rule. The independent validator is an active recovery gate, not a
reporting-only component.
Escalate when:
- scope solve is INFEASIBLE;
- scope solve is NO_INCUMBENT within its allocated tier budget;
- a candidate fails the required-work/service floor;
- the independent validator rejects the candidate for a genuine
  plan-feasibility violation that can plausibly be resolved by releasing
  more legitimate future decisions;
- policy explicitly requires broader scope.
Do NOT escalate when the validator reveals an invariant/correctness failure:
- FIXED_COMPLEMENT_CHANGED;
- completed/in-progress execution facts changed;
- stable identity/membership corruption;
- stale plan/world version;
- MODEL_INVALID;
- EXECUTION_CONFLICT caused only by immutable facts;
- validator/model-policy inconsistency or other implementation defect.
Those are correctness failures. Return the appropriate failure and fix the
model/implementation; do not widen scope to hide them.
Why: A broader scope can solve a real crew/resource/window conflict. It cannot legitimately repair a bug where the supposedly
fixed complement changed. This preserves the validator's authority without turning escalation into a bug-masking mechanism.

GATE

 preserve the checkpoint note plus a patch/diff of only this task's changes instead.
